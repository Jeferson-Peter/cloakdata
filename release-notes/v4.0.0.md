# CloakData 4.0.0

Rules on the same target now compose in list order. Conditions still read
original input values. HMAC-SHA256 is available for keyed pseudonymization.
Wheel and source distribution builds now include the Python modules, and CI
tests both installed distributions before publication.

## Migration

- Review any rule list that depended on later transformations reading the
  original target. Each transformation now reads the previous result.
  Conditions, including those on the target itself, still read the input
  snapshot. The `is_false` condition still matches null flags.
- Run `cloakdata.validate.validate(config)` before processing. Unknown
  methods, malformed rules, and invalid regexes now raise errors. Validate
  representative input too, since missing unconditional target columns and
  incompatible data types require a DataFrame to check. A missing conditional
  target still starts as null.
- Keep `drop` as the only rule for its column. Both `"drop"` and
  `{"method": "drop"}` remove the column. Use `month` or `year` for
  `round_date`; unrecognized modes now raise an error.
- `replace_by_contains` applies the first mapping that matches the input
  to that rule. Put multiple replacements in separate rules to chain them.
- `hash_value` preserves existing non-null digests. With
  `preserve_nulls=False`, null now receives the digest for the empty string.
  Use `hmac_value` for keyed pseudonyms and keep the key in a secret store.
  See the [privacy guidance](../README.md#privacy-and-threat-model) for limits
  and key handling.

Custom methods still use `(df, col, params) -> pl.Expr`. See
[validation and troubleshooting](../README.md#validation-and-troubleshooting)
for exception behavior and the [benchmarks](../docs/benchmarks.md) for measured
performance and memory trade-offs.

## Polars compatibility

The minimum is Polars 1.39.0. CI tests the locked 1.39.0 and Polars 2.1.0;
the full test suite also passed locally with 1.44.2. Keep Polars pinned in
pipelines that need identical hash buckets or seeded outputs across runs.
Polars [does not guarantee stable hash values across versions](https://docs.pola.rs/api/python/version/2/reference/expressions/api/polars.Expr.hash.html).
